Project Name: "EdFlow By AlgoriSync"

============================================================
1. PROJECT OVERVIEW
============================================================

Build a complete, professional School Management System designed
initially as a completely offline-first application for a single school.

The system must provide one integrated solution for school
administration, students, parents, teachers, staff, academics,
attendance, timetable, examinations, fees, HR, transport, library,
inventory, communication, reporting, security, and backups.

The first version does NOT require campus or branch management.

The system should work on a local school network (LAN/Wi-Fi) without
requiring the Internet for its core functionality.

Internet connectivity should only add optional capabilities such as
WhatsApp, email, cloud services, or online integrations.

The architecture should remain modular so that multi-campus,
multi-school, cloud/SaaS, mobile applications, and other future
features can be added later without rebuilding the entire system.

9. AUTOMATIC TIMETABLE GENERATOR
============================================================

A major feature must be a ONE-CLICK automatic timetable generator.

The system must generate a complete timetable automatically using a
built-in offline scheduling engine.

The generator should consider:

HARD CONSTRAINTS:
- No teacher double booking
- No class/section double booking
- No room double booking
- Teacher availability
- Class availability
- Room availability
- Required subject periods
- Lab requirements
- Special room requirements
- School working days
- Break periods

SOFT CONSTRAINTS / PREFERENCES:
- Preferred subject periods
- Difficult subjects earlier in the day
- PE preferences
- Laboratory preferences
- Maximum consecutive teacher periods
- Maximum consecutive class periods
- Teacher free periods
- Balanced subject distribution
- Avoid unnecessary gaps
- School-specific preferences

The system must generate simultaneously:

- Class timetable
- Section timetable
- Teacher timetable
- Room timetable
- Subject timetable
- Free-period timetable
- Master timetable

TIMETABLE WORKFLOW:

1. Configure academic structure
2. Configure teachers
3. Configure subjects
4. Configure rooms
5. Configure periods
6. Configure teacher availability
7. Configure subject requirements
8. Configure school preferences
9. Click "Generate Timetable"
10. Validate constraints
11. Optimize schedule
12. Show conflicts, if any
13. Allow review
14. Approve
15. Publish

The system should allow:

- Locking existing timetable entries
- Regenerating only selected classes
- Regenerating selected teachers
- Regenerating selected days
- Manual drag-and-drop editing
- Immediate conflict detection
- Timetable versioning
- Draft timetable
- Approved timetable
- Published timetable
- Archived versions
- Change history

TECHNOLOGY:

Use Google OR-Tools CP-SAT as the primary deterministic offline
constraint solver.

AI must NOT be required for timetable generation.

Optional future local AI can convert natural-language instructions into
structured timetable preferences.

Example:

"Generate timetable for Grades 6 to 10. Keep Math and Science before
lunch, PE in the last two periods, and do not assign more than three
consecutive periods to a teacher."

The AI layer can interpret this instruction, but OR-Tools remains the
actual scheduling engine.

12. SMS & WHATSAPP COMMUNICATION
============================================================

The system must support an offline-first communication architecture.

A local Android Communication Gateway can be connected to the school
computer/server.

Example architecture:

Django School System
        |
        | Local API / USB / LAN
        v
Android Communication Gateway
        |
        +---- SIM ---- SMS
        |
        +---- Internet ---- WhatsApp

SMS can be sent using a SIM installed in the Android device.

This avoids making the core system dependent on an external SMS API.

For WhatsApp, the Android gateway may be used where technically and
operationally appropriate. WhatsApp itself requires Internet access.

Do not make the entire school system dependent on WhatsApp.

COMMUNICATION QUEUE:

Every outbound message should have:

- Recipient
- Message
- Message type
- Template
- Priority
- Created time
- Scheduled time
- Status
- Attempt count
- Sent time
- Failure reason
- Gateway device

Statuses:

- Pending
- Processing
- Sent
- Failed
- Cancelled
- Scheduled

The system should retry failed messages where appropriate.

30. VIRTUAL ENVIRONMENT
============================================================

The project MUST use a dedicated Python virtual environment.

Create:

    .venv

The .venv directory is local to each development/deployment machine and
must NOT be committed to Git/source control.

Create and maintain a root-level:

    requirements.txt

requirements.txt MUST contain all Python dependencies required to install
and run the project.

Recommended setup:

    python -m venv .venv

Activate on Windows:

    .venv\\Scripts\\activate

Upgrade pip:

    python -m pip install --upgrade pip

Install project requirements:

    pip install -r requirements.txt

When dependencies are added or removed, requirements.txt must be updated.

The project should include an easy Windows setup script, for example:

    setup_windows.bat

The script should:

- Check that Python is installed
- Create .venv if it does not exist
- Activate/use the virtual environment
- Upgrade pip
- Install requirements.txt
- Show clear success/error messages

Do NOT copy an existing .venv between computers. Recreate the virtual
environment from requirements.txt on each deployment machine.

Recommended project structure:

Project Root/
    .venv/                  # local only; not committed
    requirements.txt        # mandatory dependency list
    setup_windows.bat       # easy setup
    manage.py
    project/
    apps/
    templates/
    static/
    media/
    documentation/
    backups/
    .gitignore

============================================================
36. OFFLINE QUEUE
============================================================

Internet-dependent messages should never break the school system.

Example:

A student is marked absent while Internet is unavailable.

The system stores:

    Message: Student absence notification
    Recipient: Parent
    Type: SMS/WhatsApp
    Status: Pending

When the Android gateway/network becomes available, the gateway processes
the queue.

This ensures the school can continue operating normally offline.
